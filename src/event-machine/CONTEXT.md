# 이 Event Machine 라이브러리가 만들어진 이유: XState와 useReducer의 한계

## 핵심 문제: 외부에 닫혀 있다

XState와 useReducer는 상태 모델링에 강력한 도구다. 선언적으로 상태를 표현하고, 구현과 인터페이스를 분리할 수 있다. 그런데도 실제로는 잘 안 쓰인다.

이유는 **외부 상태에 닫혀 있기 때문**이다.

"외부에 닫혀 있다"는 것은 이런 의미다:

- 외부 상황을 무시하고 자신의 내부 상태만 철저히 관리한다
- 오직 이벤트를 통해서만 소통하려 한다

## React 생태계와의 충돌

React 컴포넌트 생태계에서 가장 강력한 힘을 가진 것은 **props로 전달되는 외부 상태**다.

하지만 reducer나 XState는 이 외부 상태를 다루기 까다롭다. 외부에서 주입되는 상태 변화에 유연하게 반응하기 어려운 구조이기 때문이다.

## 그래서 언제 쓸 수 있나?

XState나 useReducer가 제 기능을 발휘할 수 있는 곳은 한정적이다:

> **외부 상태에 영향받지 않는, 기능의 최상위 루트 컴포넌트**

즉, 스스로 상태의 주인이 될 수 있는 곳에서만 효과적이다.

## 아까운 유산

그럼에도 XState의 **상태 차트(Statechart)** 개념 자체는 매우 유용하다. 복잡한 상태 전이를 시각화하고, 불가능한 상태를 원천 차단하며, 상태 로직을 명확하게 표현할 수 있다.

하지만 "외부에 닫혀 있다"는 구조적 한계 때문에 실무에서 채택되지 못하고, 결국 이 귀중한 개념들이 개발자들에게 습득되지 못한 채 버려지고 있다.

**도구의 한계가 개념의 가치까지 묻어버리는 셈이다.**
